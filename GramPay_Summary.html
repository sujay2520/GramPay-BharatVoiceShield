1. Executive Summary & The Problem

With the nationwide rollout of NPCI Hello! UPI and UPI 123Pay, over 500 million Indian citizens—predominantly rural farmers, senior citizens, and first-time digital banking users—can now authorize financial transfers using natural voice telephone commands on feature phones without smartphone literacy.

However, conversational voice banking has introduced critical vulnerabilities:

⚠️ 3-Second Neural Voice Clones

Fraudsters harvest a short voice clip from WhatsApp or spam calls and use low-latency neural vocoders (XTTS v2, ElevenLabs, RVC) to clone a farmer's voice, tricking bank voice agents and draining life savings.

⚠️ Economic LLM Token Drain

Traditional voice bots execute Speech-to-Text (STT) and Large Language Model (LLM) reasoning before authenticating the caller, burning ₹10 to ₹20 in GPU compute on fraudulent or wrong-number calls.

2. The GramPay Solution

GramPay (BharatVoice Shield) is a zero-trust, high-assurance security and cost-optimization gateway that sits inline between cellular telephony networks (SIPREC / WebRTC / PSTN) and conversational AI banking agents.

🛡️ Zero-Trust Pre-Gating

Acoustic biometrics execute before any LLM token is spent or banking API is triggered. All fund execution tools remain 100% HARD-LOCKED until voice liveness is mathematically proven.

⚡ Stage-B Active Challenge

On noisy 8kHz cellular lines, NVIDIA Nemotron-3.5 generates an unpredictable 4-word phrase. Real-time voice conversion tools buffer (>800ms) and expose vocoder phase artifacts that are blocked immediately.

4. Step-by-Step Call Workflow: How It Works

1
Citizen Call Ingestion (Cellular Telephony / WebRTC)

A farmer (e.g. Ramesh Patel) calls the bank's Hello! UPI number. The telephony media stream is forked at the Session Border Controller (SBC) via SIPREC into GramPay's FastAPI gateway. Audio is normalized and segmented (≥ 4.0s).

2
Silent Inline Dual-Engine Screening (< 300 ms)

GramPay dispatches the audio in parallel to DetectifAI's Aletheia (synthetic detection) and Eidos (speaker verification). The conversational LLM and banking tools remain completely idle and locked.

3
Deterministic 3-Tier Policy Router (gate.py)

Authorization is decided by strict, auditable Python policy logic—never left to probabilistic LLM judgment:

  • Tier 1: Approve Natural human voice (synth < 0.62) & speaker match (similarity ≥ 0.53) $\to$ Tool Unlocked. Payout to IFFCO Fertilizer executes.
  • Tier 2: Step-Up Challenge Borderline audio (0.50–0.62) or 8kHz noise $\to$ Triggers NVIDIA Nemotron Active Challenge.
  • Tier 3: Block Alert Computer clone detected (synth ≥ 0.62) $\to$ Immediate call termination (<300ms), funds frozen, bank fraud desk alerted, ₹20 saved.
4
Mutual Agent-to-Agent Identity Handshake

To prevent rogue bots impersonating banks, GramPay issues single-use, 60-second JWT credentials signed via HS256. Every credential is confirmed in SQLite with an immutable nonce registry to reject replay attacks.

5. Stage-B Dynamic Cognitive Challenge (NVIDIA Nemotron)

🎙️ Anti-Buffering Latency Defense

When 8kHz cellular compression causes uncertainty, NVIDIA Nemotron-3.5 generates a non-repeatable 4-word phrase: "Namaste Ramesh ji, kripaya ye shabd boliye: Green monsoon lotus peacock".
Human vocal response latency is naturally < 800ms. Real-time voice conversion tools (RVC / ElevenLabs STS) require 600ms–1150ms of computational audio buffering, triggering an instant liveness breach.

6. Fail-Closed Security Posture (Rule 5.4 Compliance)

In accordance with Hackathon Rule 5.4, GramPay enforces Zero Mock Scores and a strict Fail-Closed architecture:

  • If DetectifAI APIs time out, return 5xx, or network drops, the gate unconditionally defaults to BLOCK for payouts and STEP_UP for inquiries.
  • Sensitive banking tools (pay_merchant, transfer_funds) are instantiated in a locked state and cannot execute without a cryptographically valid approval token.
